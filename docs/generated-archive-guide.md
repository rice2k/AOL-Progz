## Project scope

The archive is not only a software-file collection. It combines application inventories, recovered/mirrored files, author and category research, historical download/source URLs, external mirror discovery, archive-text clues, recovered web media, and large manual-review queues.

## Research layers

### Main application catalog
The central inventory tracks known applications and attempts to improve names, authorship, categories, AOL/version associations, descriptions, and source information.

### File preservation
The research workspace distinguishes catalog records from mirrored files and recovered external material. This is important because a program being documented does not necessarily mean an original file has been recovered.

### URL and mirror research
Thousands of source/download links were crawled and deduplicated. Mirror leads provide potential alternate recovery paths for files whose primary historical source disappeared.

### Archive-text clues
Readable text extracted from historical archives can provide evidence about a program's purpose, AOL/version compatibility, URLs, descriptions, and naming. These clues should be treated as evidence with provenance rather than silently converted into certainty.

### Authors and conflicts
The archive includes author research and conflict/manual-review work. Where sources disagree, the disagreement should remain visible until stronger evidence resolves it.

### Manual review queues
The large high- and medium-priority queues show that this is an active research archive. Automated inference should not be presented as verified metadata without review.

### Recovered web media
Recovered web images and source-site research can help reconstruct the historical context surrounding programs without modifying the preserved program files themselves.

## Recommended preservation labels

- **Verified** — supported by a direct/reliable source.
- **Recovered** — original or historical file/material has been obtained.
- **Mirrored** — preserved copy from a mirror/archive source.
- **Inferred** — metadata derived from indirect evidence.
- **Lead** — possible source or recovery route requiring verification.
- **Needs review** — unresolved/conflicting/incomplete record.

## Documentation priorities

1. Preserve the main catalog and its schema.
2. Retain provenance for recovered/mirrored files.
3. Preserve URL/source research even when links are now dead.
4. Keep inferred metadata distinguishable from verified metadata.
5. Document author conflicts and unresolved cases.
6. Preserve review queues so unfinished research remains actionable.
7. Add screenshots and examples that make large generated datasets understandable.
8. Retain statistics/build notes so future archive generations can be compared.
